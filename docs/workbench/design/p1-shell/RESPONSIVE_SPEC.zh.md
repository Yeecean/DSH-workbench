# P1 响应式布局设计

[English](RESPONSIVE_SPEC.md) | 中文

## 摘要

本设计沿用原生 Frame 的空间让步顺序；拟议 Context Slot 仍以[右栏 ADR](../../GLOBAL_RIGHTBAR_ADR.zh.md)为准。下列数值描述现有源码，不能视为原型行为已验证。

## 原生几何规则

当前列宽求解器在普通右轨道存在时保护 400 px 的中间区域，右轨道至少需要 300 px，可用空间不足时移除该轨道（[columns.ts:10–31, 44–63](../../../../packages/client/ui-layout/src/client/columns.ts)）。侧栏低于 768 px 时使用抽屉，低于 1024 px 时自动折叠，用户仍可交互调整（[columns.ts:20–25](../../../../packages/client/ui-layout/src/client/columns.ts)、[stores.ts:107–124](../../../../packages/client/ui-layout/src/client/stores.ts)）。这些是框架测量值和源码规则；外层窗口宽度或设计稿标签本身不能证明实际布局。

## 按实测框架宽度设计的拟议行为

以下尺寸用于设计与验收检查。普通右轨道能否显示还取决于侧栏状态、用户偏好、选中所有者、全屏模式和实际求解结果；不能硬编码另一套相互独立的列宽算法。

| 框架宽度 | 侧栏意图 | 主区域与右栏意图 |
|---|---|---|
| 1440 px | 用户偏好允许时展开导航。 | 求解允许时显示可读的主区域和唯一选中的 Context 或原生 Session 轨道，提供一个拖动手柄。 |
| 1280 px | 保留用户设置的展开或折叠导航及其偏好。 | 符合条件时保留主区域和单个选中右栏；检查两种所有者宽度及受限文本。 |
| 1024 px | 检查自动折叠边界两侧；源码自动条件是低于 1024 px，而非等于该值。 | 按实际侧栏宽度由求解器判断选中轨道是否容纳；较宽的展开侧栏可能改变结果。 |
| 768 px | 源码抽屉条件是低于 768 px，因此此处尚未进入抽屉；侧栏可能处于折叠轨道状态。 | 保持主内容可用，仅在实际求解允许时显示单条普通轨道；检查阈值两侧。 |
| 767 px 及以下 | 使用源码规定的抽屉行为，确保重新打开控件可触达。 | 保留主要任务，提供可访问的 Context/Session 选择或重新打开路径。原生 Session 在低于 768 px 时计算自动全屏；拟议 Context 窄屏呈现尚未验证。 |

普通轨道放不下时，保留 Session 和 Context 的逻辑打开意图及各自首选宽度；布局让步不能当成用户关闭。不能为了给 Context 腾空间而强制将 Session 位置的 `canShow` 设为 false，因为这可能改变其展开状态（[SidebarRight.tsx:397–413](../../../../packages/client/ui-sidebar-right/src/client/shell/SidebarRight.tsx)）。具体窄屏呈现需要批准和 Windows 实测。

## 必须进行的评审

在 Windows Native Desktop 上测量每个检查点及阈值两侧的实际框架与列宽。检查拖动取消和窗口缩放、UI 与终端字体变化、系统缩放、Windows 标题栏安全间距、焦点转移、较长翻译标签、抽屉开关，以及原生全屏和 Context 切换。避免裁切控件，保持主内容可读及 Terminal、Files 的紧凑密度。

包括动画期间在内，检查只有一个右栏可接收指针、键盘焦点和无障碍遍历。Renderer 重载和恢复需要单独验证；本设计不承诺持久化，也不声称原型已经通过这些检查。

## 开发备注

视觉原型只说明响应式意图；实际 AppFrame 几何和无障碍行为仍需在 Windows Desktop 上验证。
