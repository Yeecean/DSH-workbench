# 方向 A（原生延续型）与方向 B（轻度产品化型）评审对比报告

## 1. 逐维度对比

| 评估维度 | 方向 A：原生延续型 (`dir=native`) | 方向 B：轻度产品化型 (`dir=product`) | 结论与取舍 |
|---|---|---|---|
| **与原生组件的兼容性** | **极高**。完全使用 `--dsw-alias-bg-base` 与 `--dsw-specific-sidebar-fill` 实色表面。 | **高**。原生 Conversation、Approval、Terminal (`xterm`) 与 Files 保持 100% 原有实色表面与交互结构，绝不重绘。 | 两套方向均严守不破坏原生功能身份的红线。 |
| **视觉识别度** | **偏弱**。Home 与全局 Context 接近普通配置列表，缺乏 Workbench 壳层的空间锚点。 | **清晰且克制**。通过顶部轻量控制栏、Home 分组卡片和 Context 作用域分层建立清晰的 Workbench 产品识别。 | 方向 B 更符合 V2「精致、通透、克制、有空间层次」的目标。 |
| **信息密度与长时间阅读舒适度** | 全局统一紧凑（内边距 24–28px，组间距 14px）。长时间浏览 Home/Context 略显局促。 | **分层密度**：Home 与 Context 舒展（内边距 36px，组间距 20px）；Terminal、Files、代码块保持原生高密度行距。 | 方向 B 兼顾浏览呼吸感与技术工作区的高效密度。 |
| **对比度与无障碍** | 实色背景正文对比度 ≥ 11.4:1，焦点环 `2px solid`。 | 玻璃表面配显式 1px 边框与高对比前景（实测正文对比度 ≥ 9.8:1，满足 ≥ 4.5:1；控件/焦点 ≥ 3:1）。 | 两者均满足对比度与键盘焦点可达要求。 |
| **GPU/合成性能与兼容性回退** | 零模糊开销。 | 仅在顶栏、右栏头、Popover 和抽屉遮罩使用单层 `backdrop-filter: blur(14px)`；内置 `prefers-reduced-transparency` 与无 `backdrop-filter` 时的 100% 实色回退。 | 方向 B 避免多层大面积模糊，性能可控且回退完整。 |
| **对主题系统与 Token 的影响** | 仅消费现有 `--dsw-alias-*` 与 `--dsh-*` 变量。 | 复用原生 `ThemeRuntime`，仅补充受控的壳层材质与间距语义角色，不新建平行 Theme Runtime。 | 方向 B 扩展边界清晰，不会造成主题切换断层。 |
| **实现成本** | 最低。 | 中低（仅在 Workbench 新增组件与壳层样式中增加材质与实色回退规则）。 | 方向 B 的边际实现成本低，但产品体验提升显著。 |

## 2. 推荐结论（待用户批准）

**推荐采用「方向 B：轻度产品化型」**，理由如下：
1. **原生身份零割裂**：Conversation 消息主体、工具审批、Terminal 输出、Files 文件树和设置表单全部固定在稳定的不透明语义表面上，不会因引入毛玻璃而影响代码与终端阅读。
2. **层级与呼吸感更优**：Home 与 Global Context 通过分组间距和受控顶栏材质，清楚区分了「全局壳层/工作区上下文」与「具体 Session 会话工具」。
3. **完整的实色回退保障**：当用户关闭透明效果、系统启用减少透明度或硬件环境不支持模糊时，方向 B 自动退化为与方向 A 等价的高对比度实色表面。
